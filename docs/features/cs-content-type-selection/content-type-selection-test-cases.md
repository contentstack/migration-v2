## Gaps / Needs Clarification

- **Page size is 25, confirmed.** feature.md Q-3 is resolved and trd.md TC-2 records the choice; feature.md AC-2.1, AC-2.2, AC-2.6, AC-3.1 and AC-3.2 have been updated to match. Retained here only as a note that the prototype used 8 — a case written from the prototype rather than the spec would use the wrong figure.**What `Merge` does to entries is undefined.** feature.md Q-1 / prd.md PQ-6 record this as deferred, and feature.md A-3 restricts `Merge` to a schema outcome. No test case can assert entry behaviour for a merged content type, so the `Merge` mode is covered here only as a recorded decision, never as an outcome.
- **Exact copy is unspecified for five user-visible strings.** The documents pin verbatim copy for the conflict explanations (FR-5.9), the status line (FR-8.1, FR-8.2) and the primary action (FR-8.4), but not for: the empty-search-result state (FR-3.8), the destination-unreadable message (FR-2.4), the untick confirmation dialog's full sentence (FR-6.3 requires only that it names the referencing types), the save control's label (FR-9.2 requires only that it states a count), and the select-all label outside a search (FR-4.5 specifies only the search-active form). Cases covering these assert structure and content, not exact wording.
- **No numeric threshold for client-side responsiveness.** NFR-2 requires that no network request is issued per keystroke or per tick, which is testable, but states no latency target for the interaction itself. The confirmation-lookup performance case is therefore marked manual.
- **Concurrency behaviour is documented but not decided.** EC-9 states last-write-wins and feature.md Q-5 / trd.md TQ-3 leave open whether that is acceptable. The test case records the current behaviour rather than asserting it is correct.
- **Whether unsatisfiable references should be blocked or warned at save time is unresolved.** feature.md R-2 and Q-6 / prd.md PQ-4 note that an operator who simply never ticks a referenced content type receives no warning at all — only unticking triggers one. No test case asserts a warning in that path, because no document states one should exist.
- **API-1's inclusion of the persisted selection is unresolved.** trd.md TQ-1 asks whether the persisted selection belongs in the inventory response or in a separate fetch. Cases here follow the bundled shape described in trd.md §6; if TQ-1 resolves the other way, those cases change.
- **Full replacement vs partial update on persist is unresolved.** trd.md TQ-4 leaves this open while §6 describes full replacement. The replacement test case follows §6.
- **`Move to review`'s target after interfaces 2 and 3 exist is unresolved.** trd.md TQ-5 notes the action advances to the Preview step today, but may need to advance within the Content mapping step once the later interfaces are built. Cases assert today's behaviour only.
- **Two product goals are unmeasurable and therefore untestable.** prd.md G-5 (whether operators change the conflict default) and G-6 (whether scoping reduces failed migrations) have no instrumentation, recorded as PQ-2. They appear here only as manual usability observations, which is not the same as a metric.
- **Whether chosen conflict modes are logged is unresolved.** trd.md TQ-6 / prd.md PQ-2. The observability case asserts that counts are logged, because trd.md §11 states that; it does not assert the modes themselves are, because that is explicitly open.
- **Case sensitivity of the search is stated; case sensitivity of the destination match is the opposite.** FR-3.4 requires a case-insensitive title search while FR-2.3 requires a case-sensitive uid match. Both are tested as written, but the asymmetry is deliberate-looking rather than confirmed, and is worth a second read before it becomes a defect report.
