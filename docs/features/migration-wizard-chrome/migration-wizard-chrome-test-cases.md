## Gaps / Needs Clarification

- **App-bar step titles for four of the seven steps:** the titles for Source, Destination, Migrate and Verify are undecided (feature.md FR-5.5, Q-4 / prd.md PQ-5), and the spec notes they are *not* simply the tracker labels. TC_MWC_002 therefore asserts only the "Step 3 of 7 · " prefix, and TC_MWC_041 covers only the three titles the design does specify. No test asserts a title for the other four steps.
- **Primary-action labels and status lines for Migrate and Verify:** undecided (feature.md FR-5.1, FR-5.2, Q-3 / prd.md PQ-4). TC_MWC_040 covers only the five steps whose labels are specified; no cases exist for the Migrate or Verify steps' footer copy.
- **Disabled-state explanations beyond Source and Audit:** feature.md FR-5.4 specifies explanation copy only for those two steps (Q-3). TC_MWC_034 tests that *an* explanation appears, but no case asserts its wording for the other five steps.
- **Unknown or not-yet-reached step in the route:** expected behaviour is undecided (feature.md EC-5, EC-6, Q-8 / trd.md TQ-8) — redirect to the furthest reachable step, redirect to Source, or render anyway. No test case is written until the behaviour is defined.
- **Back while a panel's advance work is in flight:** expected behaviour is undecided (feature.md EC-10, Q-9 / trd.md TQ-3). TC_MWC_031 covers re-entrancy on the primary action only; the interaction between Back and an in-flight advance is untested.
- **Narrow-viewport treatment of the seven-step tracker:** undecided (feature.md NFR-6, EC-9, Q-7 / prd.md PQ-7); the design provides no mobile layout. TC_MWC_052 tests only the stated absolute rule ("must not scroll horizontally"), not any specific collapse or scroll behaviour.
- **Performance budget for the source-indicator read:** feature.md NFR-4 states the no-re-fetch rule but leaves the numeric budget `TBD` (Q-5 / trd.md TQ-5). TC_MWC_051 tests the no-re-fetch rule only; no case asserts a latency threshold.
- **Supported browser matrix:** undecided (feature.md NFR-5, Q-6 / prd.md PQ-6). No compatibility test cases are included.
- **Per-step completeness test:** the direction is settled (a step is complete when its own persisted document exists and is valid), but the specific test for each step is not confirmed — in particular whether Source requires a *succeeded export* rather than merely a persisted selection (feature.md Q-2 / prd.md PQ-1 / trd.md TQ-1). TC_MWC_009/010/011 assert the tracker's rendering given a known set of complete steps; they do not assert how completeness is determined.
- **Tracker completion for unbuilt steps:** trd.md TRR-1 records that a step with no persisted document can never read complete, so with five of seven steps unbuilt the tracker cannot show them complete regardless of user activity. TC_MWC_011 (Verify step, six complete) is therefore only exercisable once those steps persist state, or against a synthetic completeness context.
- **Audit-step cases have no real panel:** TC_MWC_022, TC_MWC_023, TC_MWC_024 and TC_MWC_036 specify Audit-step behaviour, but the Audit step does not exist yet (trd.md §10). They must be driven with a synthetic Audit-shaped step context rather than a real panel.
- **Centred column width:** the design uses 1100px for the app bar and footer while an existing panel uses 1180px, so as-designed the footer would not align with the panel above it (feature.md A-5, Q-10 / trd.md TQ-6). No alignment test case is written until the intended width is confirmed.
- **Analytics events:** prd.md §10 lists three proposed events but no analytics pipeline is confirmed (PQ-2), so the metrics counters in trd.md §11 are not observable. TC_MWC_053 covers only the NFR-7 logging requirement, not metric emission.
